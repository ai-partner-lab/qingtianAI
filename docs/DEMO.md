# 演示、上手与重置

## 开场先贴标签

| 演示方式 | 展示内容 | 必须说明 |
|---|---|---|
| **合成** | `selftest` 或 `tour` 的临时数据和状态。 | 不启动真实 Worker，不证明真实模型、账户恢复或业务验收。 |
| **文字回放** | 按 [场景库](SCENARIOS.md)讲述新编通用对话及证据清单。 | 是讲解脚本，不是假实时任务、原始用户记录或可执行指令。 |
| **真实运行** | 在新建通用项目、有效授权和已接入宿主中实际执行。 | 必须给出环境／版本、产物及原始回执；需要另行批准，本文不会自动运行它。 |

三种方式不能混剪成一条“全部已经发生”的证据链。本轮场景文档不新增真实执行验收；不要把已验证历史候选算作后来兼容改动的验证。

## 空工作台与无凭据自检

```bash
qingtian selftest
qingtian quickstart --open
```

selftest 在临时库运行 8 项无凭据检查，明确返回 `model_called=false`、`business_acceptance=false`。检查覆盖状态、幂等、证据门、manual 不领取、持久化、SQLite 完整性与看板投影；不启动 HTTP 服务或浏览器。quickstart 首次使用新数据目录时启动真实空库，重启会保留该目录已有任务；“能力与上手”支持下一步、上一步及展开能力。浏览说明不创建/推进任务。

quickstart 默认后台运行，关闭终端不会停止；请用同一数据目录的 `qingtian stop`。需要隔离演示时使用下述 tour，或按 [接入手册](ADOPTION.md) 选择新的私有数据目录。

## 合成 tour

```bash
qingtian tour --port 8767 --open
```

同一引擎、临时库、5 张明确标记的合成状态卡；不启动 Worker。

**重置：Ctrl+C 结束 tour，再运行。** 每次新临时库，退出清理，不碰真实数据。真实工作台没有“一键抹掉任务”；新一轮验收请选新私有 `--data-dir`。

## 五分钟讲解顺序

这条讲稿仅需合成 tour 与文档文字回放，不必故意耗尽额度、启动模型或创建真实执行任务。

| 时间 | 画面／动作 | 讲述重点与标签 |
|---|---|---|
| 0:00–0:40 | 展示本页的三种标签，再看“能力与上手”。 | “接下来是合成界面加文字回放。公库原语、宿主适配和人工协调不是同一层。” |
| 0:40–1:20 | 在 tour 查看合成卡片和任务详情。 | “task 是工作，run 是一次尝试，evidence 是回执。现在没有真实模型在执行。” |
| 1:20–2:50 | 切到下文的“只说一次继续”文字脚本。 | 展示核实中断、保留授权、只派剩余、释放入口；这是宿主辅助协调的通用化讲法。 |
| 2:50–3:40 | 展示 [缺证据](SCENARIOS.md#s06)和 [外部等待](SCENARIOS.md#s05)清单。 | “本地代码交了，不等于供应商已接通；缺哪份回执，由谁补，要写清楚。” |
| 3:40–4:30 | 展示 [发布继续暂停](SCENARIOS.md#s08)。 | “继续本地工作，不恢复旧部署。不改验收要求，也不替用户扩大授权。” |
| 4:30–5:00 | 回到接入入口，Ctrl+C 退出 tour。 | 邀请按新通用项目另行验收；不把合成 DONE 卡片作为完成证据。 |

架构说明可以作为附加段落，沿用 [全景 Excalidraw](diagrams/engine-overview.excalidraw)与 [执行闭环 Excalidraw](diagrams/engine-lifecycle.excalidraw)，按请求、项目映射、Worker、证据、反馈讲解。PNG/SVG 与 canonical 场景配套；本轮不新画图、不改既有图。

## 主打场景脚本：只说一次继续

**标签：文字回放。以下是虚构通用对话，不是宿主命令、CLI 参数或实际执行记录。**

```text
用户：刚才没 token 了，现在可以了，继续。
大管家：我先核对原中断和当前可执行条件，定位对应执行任务，保留已批准方案。
讲解者：这里先显示“原因／条件／授权已核对”的示例清单；没有实际核实就不能打勾。
大管家：仅将未完的本地检查交回原 owner；已有修改保留，发布继续暂停。
讲解者：宿主续接回执只能说明消息已派发，不说明任务已经完成。
大管家：执行任务负责交检查结果与产物回执，我先释放入口，你可以继续提其他问题。
执行者：以下是剩余工作的实际回执、对应产物版本及未验收项。
讲解者：最后这句话只有在真实运行中拿到回执才能改标“真实”，文字回放不算验收。
```

遇到阻塞时也要演示正确回应：“当前额度仍不足／原任务无法唯一定位，这次没有派发，也没有充值、消费 reset、切换模型或解除发布暂停。”不要承诺永久回调；只有接入了有效通知机制，才能说明它会怎样通知。

## 可替换的两分钟片段

- **重启不重跑：** 展示数据目录和 manual 的核对项，解释服务恢复不等于执行恢复；不要在正式实例切 auto 演示。[场景 02](SCENARIOS.md#s02)
- **交接不丢稿：** 展示虚构检查点中的批准版本、已有产物、未提交修改及唯一 owner；不直接打开真实会话日志。[场景 03](SCENARIOS.md#s03)
- **谁来补证：** 先列缺少的测试环境／回执，再列负责方。禁止仅为舞台效果登记 `--verified`。[场景 06](SCENARIOS.md#s06)
- **失败有上限：** 展示原失败、修复范围与独立复验的位置；无真实回执时只展示空白模板，不编造通过次数。[场景 12](SCENARIOS.md#s12)

公共任务详情现在已有结构化绑定的会话导航入口和 ID 复制。演示可展示当前真实 UI 和生成链接；隔离验证未打开真实原生 Codex 目的地，不得说成已完成账户/桌面跳转。没有获准脱敏素材时用文字说明；有效角色回读、首次接入及桌面置顶仍需各自验收，不能借 UI 演示宣称整个工作流就绪。

## 另行授权真实运行时的验收单

1. 选择新建、无业务资料的通用样例项目，记录实际包／源码版本、宿主版本、模式与模型配置。确认不是正在变更的检查点。
2. 明确本轮可以创建和续接哪些执行任务、修改哪些文件、运行哪些检查，以及费用与外部动作边界。不靠耗尽真实额度制造效果。
3. 用真实失败事实或明确标为注入的合成故障验证对应分支；注入故障通过不能宣称账户限流端到端通过。
4. 保留中断前后任务／run 关联、恢复依据、批准范围、产物版本、实际回执和仍然暂停的事项。私有原始材料不进入公库。
5. 分项报告：消息派发、执行、产物、独立验收和桌面导航分别通过或未测试；进度百分比与 `item.completed` 不是完成门禁。
6. 检查退出与清理仅作用于本轮样例。凭据、知识正文、业务名、本机路径、真实会话标识与截断授权均不得进入公开录屏。

对外介绍可使用 [品宣文案](BRAND.md)。录屏、截图和报告采用新建通用样例，先检查是否包含私有路径、任务或知识内容。
