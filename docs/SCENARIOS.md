# 协作场景库：说清一次，接着把事做好

**主打体验：执行中断后，用户只对大管家说一次“继续”，不必逐个找执行者、重述已经批准的需求。** 这需要任务可识别、原授权仍有效、执行条件已恢复，以及宿主或适配器提供任务读取和续接能力；不是安装开源 CLI 后就自动获得的承诺。

这里的“大管家”是负责收件、协调、核对和反馈的智能体职责；“执行者”是承担具体实施的执行任务或智能体职责，不是人事岗位或虚构员工。引擎内的 `RecoveryCoordinator` 是本机恢复协调组件，不等同于拥有所有宿主工具的对话大管家。

本文使用全新通用文字样例。主打案例提炼自一次宿主辅助协调实践，不公开原截图、真实任务标识、路径或业务资料，也不补猜被截断的授权内容。各场景是可采用的操作约定，不能整页视作自动化功能清单。

## 能力层级

| 标签 | 含义 | 不能推导出的承诺 |
|---|---|---|
| **公库原语** | 本仓库已有状态、事件、证据、项目映射、Worker、依赖和有界恢复等基础能力。 | 原语存在不等于整个用户旅程已经自动实现或通过真实验收。 |
| **宿主／适配** | 需要 Codex 宿主工具或接入方提供任务读取、续接消息、导航、账号状态等能力，并在该环境验收。 | 不等于公共 CLI 自带全部工具，也不保证任意版本、账户或电脑可用。 |
| **人工协调** | 大管家与执行者遵守的工作约定，由操作方确认授权、文件归属和验收事实。 | 一段提示词不是强制权限隔离，也不是已上线的自动规则。 |
| **后续规划** | 公库尚未交付的集成或体验，只能作为待建设项。 | 不保证交付时间，不用演示、角色名或已有接口代替实现。 |

每个场景下方分别标注组合层级。实现清单见 [能力与验收](ENGINE-CAPABILITIES.md)，入口限制见 [大管家入口](MANAGER-ENTRY.md)。当前角色有效指令缺少可靠回读，`workflow_ready=false`；规则提交、名称或置顶元数据成功不能证明协作角色已经生效。公共 UI 已有结构化会话导航入口，真实原生目的地和首次账户/桌面协作仍未验收。

| [11 已批准方案交给设计或生成阶段](#s11) | 不被迫重复选方案或接受暗中改稿。 | 人工协调 + 对应工具接入。 |
| [12 测试失败后的有界返修](#s12) | 不陷入“再试一次”却没有新证据的循环。 | 公库有限恢复原语 + 人工返修与独立复验。 |

## 一次续接的共同约定

1. **先核实中断。** 区分账户额度、短时限流、上下文不足、进程退出、网络或权限问题；用户说“没 token”是线索，不是诊断结论。
2. **再核实能否继续。** 读取宿主可提供的额度／状态和原失败信息；无法读取时标为未知，不用反复模型调用试探。额度仍耗尽且宿主不允许新执行时保持阻塞。
3. **找准任务和唯一 owner。** 使用确切任务关联、原执行环境和检查点，不用标题相似度批量续接。无法唯一定位才请用户作必要确认，不让用户重述已有记录。
4. **带上原授权，不增加授权。** 保留目标、已批准方案、文件归属、修改、模型与推理约束、测试范围及禁止事项；特别保留暂停发布。权限或模型不可用就报告，不静默降级。
5. **只派剩余部分。** 通过当前宿主支持的方式发送续接说明，或由操作方采用已核实前置条件的引擎恢复路径。检查已有活跃尝试，避免重复派发。新增执行任务或迁移须另遵守宿主的创建与授权规则。
6. **派发后释放入口。** 大管家告诉用户哪个执行任务负责、交什么、有什么阻塞，然后结束当前协调回合。只有确实接入通知／等待机制才承诺后续通知，不许承诺永久后台回调。
7. **凭证据收尾。** 执行者交产物与实际检查回执，大管家核对后才报告结果。进度百分比、`item.completed`、进程退出、口头“完成”都不能单独当验收证据。

这份“续接单”是文字模板，不是 CLI 命令或新增 API；尖括号内容由私有任务记录提供：

```text
原任务与唯一 owner：<经核实的关联>
中断原因及恢复依据：<原失败；当前额度或环境事实；未知项>
原目标／已批准方案：<保留原批准引用，不猜缺失内容>
已完成与检查点：<产物版本；已做修改；证据；未提交内容>
仅继续：<未完成部分>
允许／禁止：<文件；环境；测试；模型要求；继续暂停的发布等>
交付与停止：<验收回执；时间或尝试上限；再次失败时的归属>
```

## 01 额度或限流中断：不用逐个找执行者

> 用户：“刚才没 token 了，现在可以了，继续。”

- **痛点：** 工作停在多个会话中的一个，用户不想找回上下文、重复解释已批准方案。
- **大管家：** 核实原失败和当前可执行条件，定位原任务与 owner，读检查点及授权，发一条只续未完的消息；回告归属后释放入口。
- **执行者：** 复用有效检查点、已有修改与批准方案，确认没有重复活跃尝试，只完成剩余实施或检查，再提交实际回执。
- **输入与权限：** 原任务关联、失败记录、检查点、仍有效授权；宿主允许读取并续接目标任务，原定模型与环境可用。不要求用户重新解释已被可靠记录的需求。
- **可见证据：** 中断分类、恢复依据、续接目标、保留与剩余清单、派发回执，最后是新产物版本和实际验收结果；派发成功本身不是执行完成。
- **停止／阻塞：** 额度仍不足、恢复状态未知、目标不唯一、原授权缺失或任务已暂停时，不继续；再次遇同一限制则回报，不无限重开会话重试。
- **真实层级：** **宿主／适配 + 人工协调**的主打案例。**公库原语**记录 run/session 并支持有前置条件的恢复，不提供跨宿主自动查额度和发消息的完整链路。这里不是恢复额度、绕过限流、自动充值、消费 reset 或静默切便宜模型；这些都不由一句“继续”授权。

账户额度与重置时间以宿主实际显示为准，不硬编码计划或次数；官方说明也将账户用量与会话功能分别说明。[OpenAI 用量说明](https://learn.chatgpt.com/docs/pricing) · [Codex CLI 会话功能](https://learn.chatgpt.com/docs/codex/cli)

## 02 关机重启：先恢复服务，不重跑一切

> 用户：“电脑重开了，把工作台接回来。”

- **痛点：** 服务不在线，但旧库里既有未完工作，也有取消、暂停和仅供参考的历史任务。
- **大管家：** 确认正确数据目录、workspace 和实例身份，按 [运维步骤](OPERATIONS.md#中断续接运行单)先恢复 manual 服务，再逐项确认仍有效的任务；不要一上来切 auto。
- **执行者：** 读取持久任务、run、产物和进程事实；符合当前授权且确有剩余工作才接续，不能凭旧 PID 判断进程归属。
- **输入与权限：** 原数据备份和配置、获准仓库、当前任务授权；恢复服务与恢复执行分别确认，不覆盖现有目录。
- **可见证据：** 健康响应中的实例身份与 manual 模式、旧任务保留、有效待续清单及新 run 关联；服务在线不等于 Worker 已恢复。
- **停止／阻塞：** 数据损坏、实例身份不符、模型不可用、权限缺失或用户暂停时止步；取消、`reference-only`、`analysis-only` 不变成实施任务。
- **真实层级：** **公库原语**提供持久化、manual 和状态核对；恢复哪些任务是**人工协调**。没有“开机即恢复所有任务”的默认行为。

<a id="s03"></a>
## 03 上下文满或执行者失联：交接工作，不赌记忆

> 用户：“那个执行任务接不上了，别丢掉前面做的东西。”

- **痛点：** 对话空间、会话可用性与代码产物是不同问题，重开可能丢掉未提交修改或导致双重执行。
- **大管家：** 先分辨上下文满、连接失败与仍在运行；确认旧 owner 停止写入后交接，优先复用可用原任务。确需新任务时先遵守宿主创建规则和当前授权。
- **执行者：** 接收产物版本、未提交修改、失败线索和下一步；先确认工作区一致，不清空脏工作树，不把摘要当作完整授权。
- **输入与权限：** 有效检查点、目标文件归属、旧执行状态、允许的交接方式及原模型要求；缺少检查点时只调查，不凭空还原。
- **可见证据：** 原／后续任务的私有关联、交接清单、修改保留记录、唯一写入 owner，以及后续新证据。
- **停止／阻塞：** 旧执行者是否存活不明、产物分叉、没有迁移权限或模型不可用时暂停交接。
- **真实层级：** **宿主／适配 + 人工协调**；**公库原语**的恢复检查点和 session 记录不是任意对话的无损上下文压缩或自动搬运能力。

<a id="s04"></a>
## 04 长任务下发：大管家仍能接下一句话

> 用户：“这个实现交给执行任务，我还想问另一件事。”

- **痛点：** 用户入口长时间忙于实现或轮询，临时问题、约束变更无人接收。
- **大管家：** 简短分析目标、找现有合适 owner，写明范围与交付后下发；通知用户归属并结束协调回合，不在入口同步等待长测试。
- **执行者：** 承接有边界的实施，详细日志保留在执行任务；出现依赖、冲突或需要用户决策时再回报。
- **输入与权限：** 明确的分析或实施意图、文件 ownership、验收要求、可用宿主派发工具；新建任务须符合宿主规则，已有任务不能因“看起来相关”擅自恢复。
- **可见证据：** 收件意图、执行任务关联、派发回执、交付约定与后续产物；用户可以继续在大管家提问。
- **停止／阻塞：** 目标冲突、找不到获准 owner 或工具不可用时说明限制，不假称已下发；无通知接入就不承诺自动回调。
- **真实层级：** 入口响应约定属于**宿主／适配 + 人工协调**。**公库原语**有收件与任务状态，但不自带通用桌面任务管理工具；manual 的明确实施 intake 仍可能启动 Worker。

<a id="s05"></a>
## 05 本地交付与外部接入：不要一句“等权限”盖住成果

> 用户：“本地部分做完了，供应商资料还没到，现在能交付什么？”

- **痛点：** 实现产物已经存在，外部凭据或资料尚缺，混写成一个“未完成”让人看不出下一步归谁。
- **大管家：** 分别列出已交付产物、尚未验证的外部接入、资料／权限的提供方和验收条件；这是人工划分交付范围，不是宣称系统自动重构父子任务。
- **执行者：** 交付允许范围内的实现及本地检查，标明合成替身；接口未接通就保持外部 E2E 未测试，不用假响应冒充供应商回执。
- **输入与权限：** 原交付范围、实际产物、外部合同或接口文档、最小权限要求；凭据走私有配置，不写公开工单。
- **可见证据：** 本地产物与回执、单独的待接入清单、等待归属、明确需要谁提供什么；未满足完整合同则不把整体标 DONE。
- **停止／阻塞：** 缺资料或权限、供应商接口不可用、需要扩大范围时保持等待。提醒记录不等于外部消息已发送。
- **真实层级：** **公库原语**提供等待分类、依赖和提醒记账；范围拆解与供应商接入属于**人工协调／适配**。因外部等待自动拆单并自动接通供应商不是已交付能力。

<a id="s06"></a>
## 06 执行结束但证据不够：明确谁补什么

> 用户：“执行者说做完了，为什么还不能验收？”

- **痛点：** 有代码或截图，却没有匹配版本的测试、产物核对或已授权部署回执。
- **大管家：** 对照 evidence profile 说明缺哪种证据、对应哪个验收点；只在原许可内指派补证职责，把需要的外部环境交给实际控制方。
- **执行者：** 交实际命令、环境、产物版本和结果；测试未跑就写未测试，不能为了过门禁写一个 `--verified` 标记。
- **输入与权限：** 当前产物、验收合同、已有 evidence 与允许执行的测试；需要部署的证据并不自动授权部署。
- **可见证据：** 缺失项与 owner、真实补证回执、登记来源及核对后的 task 状态。`run.status=DONE` 与 `task.state=DONE` 分开看。
- **停止／阻塞：** 验收环境未开放、发布暂停、证据版本不匹配时保持待验收；明确告诉用户谁需要补什么，而不是泛泛要求“再确认”。
- **真实层级：** **公库原语**实现证据门和有限补证路径；证据真实性仍依赖**人工／接入方独立核验**。`--verified` 是受信声明，不是测试执行器。

<a id="s07"></a>
## 07 并行改同一文件：先定归属，再合成成果

> 用户：“两个执行任务都要改同一个入口，别互相覆盖。”

- **痛点：** 分支各自看似完成，合成时却覆盖用户修改或同时改动共享文件。
- **大管家：** 为文件或明确区域指定唯一写入 owner，其他执行任务只交接口需求或候选补丁；合成前对齐依赖和基线，遇到非本人变更先停下协调。
- **执行者：** 在分配的 worktree 和范围内工作，保留脏树；把冲突和待合成差异交回，不使用强制回滚“清干净”。
- **输入与权限：** 文件归属表、基线、各自产物、集成负责方及被明确允许的合并与检查操作。
- **可见证据：** ownership 记录、版本明确的差异、冲突处理决定和合成后的实际检查；各分支单独通过不能代替合成验收。
- **停止／阻塞：** 同一文件存在未协调写入、基线漂移或未知修改时停止受影响合成；不自行替用户选择覆盖哪一方。
- **真实层级：** **公库原语**有 worktree、依赖、lease/fencing；文件内容归属和合并是**人工协调**。本机协调锁不等于语义级文件锁、跨机互斥或自动合并。

<a id="s08"></a>
## 08 发布暂停但其他工作继续：一句继续不等于上线

> 用户：“发布仍然暂停，文档和已批准的本地检查继续。”

- **痛点：** 用户恢复一部分工作，却担心旧部署也被一同唤醒。
- **大管家：** 在续接单中列出允许继续与仍然暂停的对象；回读相关任务状态与原部署限制，不把“环境好了”当成发布批准。
- **执行者：** 只做指定文档或本地检查，保持部署动作不运行；需要发布证据时明确列为阻塞，不去改 `requires_deploy` 或验收合同。
- **输入与权限：** 暂停指令、对应任务／环境、允许继续的范围；解除发布暂停必须有明确且针对该动作的授权。
- **可见证据：** 暂停状态保留、未派发部署的任务记录、允许部分的新产物；这不是对所有外部部署工具的全局审计保证。
- **停止／阻塞：** 原任务不能安全分离实施与部署，或恢复语义不清时，先澄清受影响范围，不冒险派发整个任务。
- **真实层级：** **公库原语**识别用户暂停等不自动领取条件；跨会话、外部流水线与自然语言恢复范围由**人工协调／适配**落实，不承诺一键全局停发。

<a id="s09"></a>
## 09 任务详情直达执行会话：不靠标题猜

> 用户：“这张任务卡是谁在做？带我去对应执行会话。”

- **痛点：** 看板能看状态，却要在多个会话间手工搜索相似标题。
- **大管家：** 先核对任务与执行会话的确切映射及宿主访问能力，再提供已存在的导航；没有映射就显示不可用，不猜链接。
- **执行者：** 在交付中保留正确关联；入口只负责导航，不因为打开会话而恢复执行或发送提示。
- **输入与权限：** 当前任务关联、可访问的宿主会话、导航适配及目标环境；真实标识只留私有界面。
- **可见证据：** 打开的会话与目标任务、owner 和环境一致；验证的是导航关系，不是该任务完成。
- **停止／阻塞：** 映射过期、目标不可访问或公共包未接适配时，说明原因并保留只读任务详情。
- **真实层级：** **公共 UI 已实现**任务详情中的结构化绑定选择、会话导航入口和 ID 复制；不会从任务正文猜会话或在点击时自动续接。已有隔离浏览器验证只覆盖页面与生成链接，未打开真实原生目的地。上方“可见证据”是接入方需另行完成的**宿主／适配验收**，不是已完成的账户/桌面跳转记录。

<a id="s10"></a>
## 10 换项目或电脑：带走方法，不继承授权

> 用户：“把这套做法交给另一个项目，旧资料只作参考。”

- **痛点：** 旧绝对路径、任务台账和知识可能被误当成新环境的可执行配置。
- **大管家：** 列出获准转移的通用方法、需脱敏资料、目标项目映射与新环境验收；跨机文件或会话转移必须单独授权。
- **执行者：** 在目标环境建立明确项目映射，核对可用开发基线、模型和最小权限；重新验证引用，不能读取未经批准的旧业务库。
- **输入与权限：** 目标仓库／电脑访问许可、可转移资料范围、新任务目标、知识来源许可与版本信息。
- **可见证据：** 新环境配置与诊断、知识来源及查询回执、新任务授权和产物；历史记录与新执行证据分别存放。
- **停止／阻塞：** 路径无法映射、来源不明、缺设备访问或任务只有历史授权时停止；不把本机路径填进另一台电脑。
- **真实层级：** **公库原语**支持项目映射、approved 知识引用与 `reference-only` 导入；迁移是**人工协调／适配**。自动跨机器搬运、分布式调度和设备农场仍是**后续规划／外部接入**。

<a id="s11"></a>
## 11 方案已批准，转交设计或生成：不用再选一遍

> 用户：“就用已经确认的方案，接着做设计稿。”

- **痛点：** 进入设计、图片生成或实现阶段时，执行者重新提问，或把已批准方向换成自己的偏好。
- **大管家：** 引用完整且有效的批准记录，明确下一阶段要交什么、哪些视觉与内容约束不能改、谁负责验收；批准记录不全才问必要问题。
- **执行者：** 复用获准参考和方案，在授权工具中完成剩余产物；工具不可用或要求存在冲突就报告，不静默换方案或伪称生成成功。
- **输入与权限：** 已批准版本、可用参考及使用权、允许的生成工具／费用范围、产物格式和阶段验收要求。
- **可见证据：** 方案到产物的对应关系、真实文件或工具回执、评审意见与尚未通过项；文字设计描述不能冒充实际生成文件。
- **停止／阻塞：** 素材缺失、付费动作未获准、有效方案冲突或工具不可用时停止受影响步骤。架构图按项目约定使用可编辑 Excalidraw，不能暗换成图片生成。
- **真实层级：** 方案沿用属于**人工协调**，设计／生成依赖**宿主或工具适配**；**公库原语**能记录任务和产物证据，不内建通用设计生成流水线。

<a id="s12"></a>
## 12 测试失败：有限返修，然后独立复验

> 用户：“按失败回执修，不要无限重试，也别改测试凑通过。”

- **痛点：** 多次尝试没有清晰原因，执行者口头成功，用户仍不知道当前版本是否可用。
- **大管家：** 核实失败日志，区分产品、测试环境与验证脚本问题；把受影响文件交给唯一 owner，规定返修范围、尝试上限和独立复验责任。
- **执行者：** 在原授权内修复，保留原失败与每次差异；测试或验收合同需要改变时先说明影响，不能删除断言或改目标让构建变绿。
- **输入与权限：** 可复现失败、对应源码／包版本、文件归属、获准测试范围、时间或尝试预算；没有真实环境就标未测试。
- **可见证据：** 原失败、修复差异、重跑命令与总数、原始输出、独立复验的版本匹配；源码随后改变，旧通过只对应旧检查点。
- **停止／阻塞：** 同因失败无新信息、预算耗尽、涉及别的 owner 或外部权限时停止并回报，不能无限重开任务。
- **真实层级：** **公库原语**有基础设施恢复、有限补证与死信记录；不是任意代码缺陷的自愈。代码返修、私有验证脚本修正和独立复验仍需**人工协调／接入**；manual 不会后台自动启动这些 Worker。

## 交付时怎么说

推荐：“已在原授权内续接指定执行任务；保留已有方案与修改，未完成部分为本地检查。执行回执尚未到齐，发布继续暂停。”

不推荐：“一键无限续命，所有任务自动恢复并上线。”

每次对外演示或验收都注明层级、环境、产物版本、实际执行范围和未验证项。历史候选的通过只对应其冻结内容，不能替运行中的兼容改动背书。本文新增的是文档场景，不代表新增运行时功能或新的真实端到端验收。
