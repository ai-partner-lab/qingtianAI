# AI 协作能力目录与开源路线

## 概念边界，不再混用“角色”

**协作职责**是规划、知识准备、执行、测试、审查、归档等分工。Q 版形象仅用于视觉表达，
不表示真人，也不证明六个独立模型已连接。生产中可以由人、AI 或已有工具承担这些职责。

**工作阶段**是七步演示中的过程。点击阶段只查看信息，不代表执行、跳过、完成或回退。
主任务的实际状态仍以控制数据库为准。

**能力模块**是可单独配置和验证的工具，例如 E2E、视觉检查或发布证据校验。
一个阶段可以包含多项能力，一项能力也可以在真实项目的多个阶段使用。当前 UI 按
主要使用阶段组织目录，不要求所有能力必须串行执行。

**Leader 与 Agent**是脑图中的职责层级。Leader 负责一个阶段，下面的专项 Agent
负责某项能力；继续展开能看到具体动作、检查条件和产物。它们不等于当前已经
启动的进程或已经连接的自主模型。具体工作是否完成，必须来自实际执行回执。

## 逐层探索调度脑图

从擎天总控展开七个 Leader；选择 Leader 后，查看其下属 Agent，再点击 Agent
和具体工作节点继续展开。测试 Leader 下可分别选择 API E2E、浏览器 E2E、
接口契约、视觉回归、跨端几何、无障碍、故障注入、性能、服务集成与移动端能力。
工作节点默认只说明职责、检查条件或预期产物，不伪造“正在执行”。

例如浏览器 E2E 的具体工作包括准备新任务、检查脑图交互、桌面流程、窄屏流程、
刷新恢复、UNKNOWN 核对、最终记录及浏览器错误检查。可以逐层看每项工作对应
的检查标识，展开该 Agent 的能力详情后独立运行整个固定 E2E 套件。
本版不提供任意叶子检查的单独执行入口；叶子是检查说明与回执定位，不是可任意
重排的生产任务。真实项目按能力或 profile 选择执行范围。

工作节点通过 `check_ids` 引用独立回执的真实检查项。尚未运行、缺失检查、依赖
阻塞、已运行失败和通过是不同情况；不能因为父节点通过，就把未覆盖的子节点
标为成功。页面保留当前打开期间最近一次能力回执，不承诺跨刷新持久化。

目录扩展字段：阶段的 `leader` 保存名称与职责；能力的 `agent` 保存名称、职责
和递归 `work_items`。工作节点包含稳定 ID、标题、类型、说明、`check_ids` 与
`children`。新增能力必须同时补目录验证与真实执行覆盖，不能只加动画状态。

## 现在可以直接独立运行什么

| 能力 | 安装条件 | 实际验证范围 | 不代表什么 |
| --- | --- | --- | --- |
| API E2E | 基础 Python 安装 | 独立临时服务的真实 HTTP、七步状态流、UNKNOWN 核对与 DONE | 不包含浏览器或业务 API |
| Browser E2E | 可选 Playwright 与浏览器 | 独立 Demo 的真实浏览器交互、刷新续看、桌面/窄屏、JS 错误 | 不是原生真机或生产业务验收 |

安装后可直接运行：

```bash
qingtian demo-check --capability api-e2e
```

从源码安装可选浏览器依赖并准备 Chromium：

```bash
python -m pip install -e '.[browser]'
python -m playwright install chromium
qingtian demo-check --capability browser-e2e
```

若从 wheel 安装，把 `-e '.[browser]'` 换成收到的 wheel 文件名后加 `[browser]`。
安装需要包源和浏览器下载；安装完成后的合成演示不会访问外部业务服务。
浏览器运行方式遵循 [Playwright Python library](https://playwright.dev/python/docs/library)
和 [browser setup](https://playwright.dev/python/docs/browsers) 的官方接口。

也可打开 `qingtian demo-web`，直接点击第 5 阶段，选择能力后“独立运行”。
不必手动完成前四步。运行会创建自己的临时服务和全新合成任务，不推进、重置或修改
主 Guide 的 Task。其内部的七步操作是被测用例，不是替用户执行主 Guide。

回执包含运行标识、能力 ID、范围、开始时间、耗时、逐项检查、阻塞原因和合成任务标识；
浏览器检查另记录实际浏览器信息。`passed` 仅表示这些检查通过，`failed` 表示已运行但
未满足检查，`blocked` 表示缺少依赖等前提。缺少配置不是成功，也不应被隐藏为跳过。

页面只能调用两个固定的本地验证入口，不能输入命令、路径或目标 URL。真实项目的测试
地址、权限、数据、预算和外部副作用需要项目适配器另行接入，不能通过这个演示服务执行。

## 能力成熟度

目录保存在 `qingtian_core/resources/capabilities.json`，随 wheel 分发。

| availability | 含义 | 页面行为 |
| --- | --- | --- |
| bundled | 已有本地内核或 CLI 能力 | 展示入口；仅明确允许的固定验证可在页面运行 |
| bundled-optional | 执行器已打包，需要可选依赖 | 可请求运行；依赖缺失返回 blocked |
| adapter-required | 通用契约已具备，项目执行器或配置仍需提供 | 展示输入、输出、前提与边界 |
| planned | 已识别可复用机制，尚未完成通用实现与验证 | 只展示路线，不提供假运行按钮 |

“已有项目里存在测试源码”“已经抽取成通用组件”“已经在新项目验证通过”是三种不同状态。
目录不会用前一种状态冒充后两种。

## 可提取的测试机制

以下是机制级的开源拆分路线，不包含任何来源项目的业务数据、测试结果或默认配置。

| 能力包 | 通用部分 | 项目需提供 | 交付优先级 |
| --- | --- | --- | --- |
| 浏览器 E2E | 多视口、setup 依赖、超时、失败截图/trace/报告、独立入口 | 路由、登录、选择器、业务断言、测试数据 | P0，本地 Demo 执行器已加入 |
| 场景契约与发现 | 场景 ID、平台、步骤、检查点、请求期望、遗漏用例检查 | 业务 feature 映射与 fixture | P0，待通用严格契约 |
| 确定性视觉回归 | 固定时间与夹具、等待字体、减少动画、平台隔离基线 | 页面、字体、截图基线、阈值和人工审核 | P0，待独立执行器 |
| 跨端几何证据门禁 | 状态指纹、capture manifest、dp/px/density 校验、缺证据阻断 | 语义几何键、状态映射、采集器与容差 | P0，待提取 |
| 无障碍 | axe 注入、范围限定、严重性筛选、结构化结果 | 页面和扫描范围、人工辅助技术验证 | P0，待提取 |

| 性能与资源预算 | CLS、播放/解码预算、滚动压力、冷/热 p50/p95 | 数据规模、可重复素材、设备和阈值 | P1 |
| 增量测试计划 | Git diff、风险域、检查集、选择理由、未知变化处理 | 项目目录映射和发布基线适配器 | P1 |
| 受测构建 | 构建一次、同一产物测试、提交与摘要绑定 | 构建工具、artifact 存储与 CI | P1 |
| 数据库与服务集成 | 临时 PG/Redis、迁移链、CAS、唯一性与回滚 Harness | 合成模型和项目迁移适配器 | P1 |
| 发布与回调 Harness | 合法转换、版本竞争、幂等回调、审计与聚合 | 发布模型和环境授权策略 | P1，先离线再接真实服务 |
| 发布证据校验 | 源码 SHA、镜像摘要、run attempt、选择与证据绑定 | CI/云端采集适配器 | P1，先解析器后采集器 |
| 安全 CI | 历史密钥、SAST、依赖/IaC/镜像扫描、工具固定 | 规则、严重性阈值、例外审核 | P1 |
| 移动端 E2E | 清状态、深链、等待 testId、截图、安装包摘要 | 应用包、appId、设备、测试数据 | P2，参考流程仍含脚手架 |
| 模型辅助视觉审查 | 截图、模型适配器、逐页意见、成本与外传约束 | 模型账号、提示词、图像授权 | P2，辅助意见而非唯一门禁 |

## 不能丢掉的事实边界

- 参考跨端机制的像素 diff 仅用于定位；阻断依据是证据完整性、相同状态指纹和几何容差。
  不将其包装成已经实现的“像素 1:1 强制门禁”。
- 参考主题测试中，CI 几何断言和特定本机环境的完整截图比较不是同一覆盖范围。
  新套件必须明确在哪里真正执行基线比较，不能只看测试文件存在。
- 移动端参考流程尚有脚手架与未接通流水线；浏览器窄屏不是 Android/iOS 真机测试。
- 内存发布 Harness 不是云端发布演练；本地性能 fixture 不是生产压测。
- 新鲜测试数据、当前受测版本、缺失数据时 blocked/not-tested 的原则应保留；原项目的
  具体实体创建流程和验收规则由私有适配器提供。

## 每个通用能力包的完成标准

1. 有独立命令、明确的输入契约、前置条件与副作用类别。
2. 有完全合成的被测样例和新鲜数据工厂，不依赖来源项目。
3. 有真实执行器以及成功、失败、阻塞、超时和重复调用测试。
4. 有版本/环境/数据来源和逐项结果；报告不能掩盖未运行的检查。
5. 有可检查的输出格式，原始日志、trace、HAR、截图与录像默认留在私有空间。
6. 在空目录从安装包启动并验证；明确 OS/浏览器/设备支持矩阵。
7. 完成密钥、路径、业务规则、原始基线和 Git 历史边界审查。

开源保留执行机制、契约、合成夹具和示例基线。排除真实账号、storageState、认证缓存、
Cookie、业务截图与录像、生产证据、云账号配置、真实知识正文及来源项目的验收预期。

## 与现有验证适配器组合

`qingtian verify` 已支持按 `profile` 选择检查，因此不需要为“只跑 E2E”重建整个系统。
项目可以声明只属于 `e2e` profile 的检查，并通过明确的可信命令授权运行。
下面只是命令形态；适配器必须由项目实际创建和审核：

```bash
qingtian verify --adapter ./project.adapter.json --profile e2e --execute-trusted-adapter
```

有本地写入时还需 `--allow-local-writes`。命令不是沙箱；portable verifier 拒绝声明为
`external` 的动作。登录、创建数据、付款或部署等真实外部动作应由项目执行器负责，
再通过受控适配器将证据关联到任务。`network` 字段是声明，不是网络隔离实现。
